## §0. What Phase 3.2 was

Sample weighting applied transversally to the backend: statistics, engines, tree builder, session, validation, reporting, stability, and wizard. Eight sub-phases (3.2.a through 3.2.h), closed on 10/10/2026.

**Invariant C1.** Without weights (`weights=None`), every numeric result, every fingerprint, and every report is bit-identical to the pre-3.2 behaviour.

**Fingerprint additions.** Three new entries: `weighted` (bool), `weight_col` (str | None), `min_child_weight` (float | None).

**Suite at closure.** 346/346 PASSED (103 tests added across the phase).

## §1. The ten decisions

### 1.1 Weighted median — interpolation at exact half-mass

When the cumulative weight of the sorted observations reaches exactly half the total weight, the function interpolates between that observation and the next. This mirrors `numpy.median` with uniform weights and preserves the C1 invariant.

- Canonical: `docs/design_decisions.md` §13.1
- Chronology: `docs/audit_log.md` 10/10/2026 (3.2.a)
- Code: `backend_v3/statistics.py::_weighted_median`

### 1.2 Pearson χ² on weighted tables — scale sensitivity

With sample weights, contingency-table cells hold sums of weights. χ² scales linearly with the total weight mass (multiplying all weights by k multiplies χ² by k). This is standard weighted-survey behaviour (Heeringa, West & Berglund 2010, §5.4). TreeGov does not normalise: the analyst decides the scale.

- Canonical: `docs/design_decisions.md` §13.2
- Methodology: `docs/methodology.md` §1.9bis
- Chronology: `docs/audit_log.md` 10/10/2026 (3.2.b)

### 1.3 C&RT surrogates — agreement is not weighted

Surrogate agreement counts binary coincidences (row matches the primary's orientation or not). There is no mass to accumulate, so the agreement is not weighted. The embedded SplitConfig inside each surrogate evaluates the genuine gain WITH weights.

- Canonical: `docs/design_decisions.md` §13.3
- Chronology: `docs/audit_log.md` 10/10/2026 (3.2.c)
- Code: `backend_v3/crt_engine.py::_best_agreement`, `_agreement_nominal`

### 1.4 Weighted variance divisor — W − 1 vs W

Weighted variance in QUEST's QDA stage uses divisor `W − 1` (weighted Bessel correction), matching standard practice when weights act as frequencies. Consequence: the QDA threshold is not invariant to weight rescaling. The alternative (`W`) would be scale-invariant but biased.

- Canonical: `docs/design_decisions.md` §13.4
- Methodology: `docs/methodology.md` §3.7bis
- Chronology: `docs/audit_log.md` 10/10/2026 (3.2.d)

### 1.5 TreeNode.w_events — informative field with empty default

`TreeNode` gains `w_events: tuple[float, ...] = ()`, the per-class weighted mass. It is purely informative: no effect on routing or pruning. The empty default preserves compatibility with hand-built nodes in tests.

- Canonical: `docs/design_decisions.md` §13.5
- Chronology: `docs/audit_log.md` 10/10/2026 (3.2.e)
- Code: `backend_v3/tree_builder.py::TreeNode`

### 1.6 Session-level weighting decisions

Two sub-decisions taken together.

**1.6.1 Check B2 (≥2 rows per class per side) is conditional on weights.** The check "each class has at least two physical rows in train and test" runs only when `weight_col` is declared. Without weights, Hamilton-Hare over row counts already prevents this pathological case, and B2 would break the C1 invariant on degenerate fixtures.

- Canonical: `docs/design_decisions.md` §13.6.1
- Code: `backend_v3/splitting.py::stratified_split`

**1.6.2 Stratification with weights: row counts, not weighted quotas.** The split is Hamilton-Hare over `n_k * train_frac` (physical rows). The weights travel with each row, not with the partition. Consequence: `train_idx` and `test_idx` are identical with and without weights (same seed).

- Canonical: `docs/design_decisions.md` §13.6.2
- Code: `backend_v3/splitting.py::stratified_split`

### 1.7 Deferred: KS/AUC/Gini of the gains table are not weighted

The aggregate KS/AUC/Gini of `GainsTableResult` remain computed on row counts in 3.2.g. The parallel `w_*` columns of each row ARE weighted. Rationale: reimplementing weighted discrimination metrics locally would duplicate the weighted logic already in `validation.py`.

- Canonical: `docs/design_decisions.md` §13.7
- Chronology: `docs/audit_log.md` 10/10/2026 (3.2.g)
- Deferred to: probably Phase 3.5 (multiclass + weighted reports)

### 1.8 Hosmer-Lemeshow scales linearly with total weight mass

Same pattern as §1.2 (χ²). Under weight rescaling by k, HL is multiplied by k. Documented as expected behaviour, not a bug.

- Canonical: `docs/design_decisions.md` §13.8
- Methodology: `docs/methodology.md` §8.9bis
- Chronology: `docs/audit_log.md` 10/10/2026 (3.2.g)

### 1.9 evaluate_oot parameter is `weight_oot`, not `use_train_weights`

The original design proposed `use_train_weights`, which was ambiguous ("apply train weights to OOT"?). Renamed to `weight_oot` (bool, default True): True = the OOT cohort uses its own weights; False = uniform weights on the OOT.

- Canonical: `docs/design_decisions.md` §13.9
- Chronology: `docs/audit_log.md` 10/10/2026 (3.2.h)
- Code: `backend_v3/session_state.py::Session.evaluate_oot`

### 1.10 PSI/CSI weighting: each cohort carries its own weights

Default convention: each cohort uses its own weights (train with train weights, OOT with OOT weights). This captures both population drift and model drift. `weight_oot=False` measures only model drift (uniform OOT weights).

- Canonical: `docs/design_decisions.md` §13.10
- Methodology: `docs/methodology.md` §8.5bis
- Chronology: `docs/audit_log.md` 10/10/2026 (3.2.h)
- Code: `backend_v3/stability.py::StabilityMonitor.report`

## §4. Operational lessons from the phase

1. **Cache is the dominant lever, not prefix size.** The 11/10/2026 Product Bill showed 93.8% of input tokens served from cache. Reducing prefix size has no meaningful effect anymore.
2. **Output is the real cost.** 55% of the block cost was `completion` (model output), five times more expensive per token than input.
3. **Burst mode, not one-prompt-at-a-time.** Verifying between prompts breaks the 5-minute cache TTL and pays write premium on the next call.
4. **Weighted variance divisor matters.** Using W − 1 vs W changes the QDA threshold when weights are non-uniform. Documented and tested.
5. **Fingerprint must reflect every configuration choice.** Three new fields are recorded; two trees with different weights or `min_child_weight` never share a fingerprint.
