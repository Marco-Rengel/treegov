# TreeGov — Fase 3.10.a: Rediseño UX/UI

**Purpose.** Este documento define el diseño del rediseño de la interfaz gráfica (GUI) para cerrar los hallazgos de usabilidad pendientes (H3-H8) documentados el 13/10/2026, tomando como referencia estructural un prototipo previo (Antigravity).

**Status.** ✅ Completada (22/10/2026). Diseño aprobado e implementado; §5 registra el estado as-built verificado contra el código. Renombrado el 24/10/2026 de `docs/3.10_design_ux_redesign.md` a `docs/3.10.a_design_ux_ui_redesign.md` para alinear el nombre con la sub-fase que documenta (las entradas históricas del `docs/audit_log.md` anteriores al 24/10/2026 citan el nombre antiguo y refieren a este mismo documento).

## §0. Alcance y Objetivos

### 0.1 Lo que 3.10.a SÍ entrega (Frontend puro)
1. **Toolbar Superior:** Reemplaza o complementa los menús con una `QToolBar` (Cargar Dataset, Configurar Árbol, Zoom, Resumen, Ganancias, etc.).
2. **Nodos de Árbol Enriquecidos (H4):**
   - Cabecera de color (Azul oscuro para nodos internos; Rojo/Verde para hojas según PD).
   - Mini-barras de proporción (Buenos/Malos).
   - Métricas adicionales en el nodo (Gini, KS, P-valor).
3. **Panel de Propiedades Derecho (H4):** Reestructurar el HUD actual para mostrar: Info del Dataset, Info del Nodo (con barra de distribución), Regla de Partición y Acciones.
4. **Tema Oscuro (H8):** Implementación de jerarquía visual real con 3 niveles de luminosidad (BG, SURFACE, SURFACE_ELEVATED) inspirados en VS Code Dark+.
5. **H3:** Botones de mover predictores con iconos Unicode (`→`, `⇒`, `←`, `⇐`) y tooltips.
6. **H5:** Tooltip "Disponible en Fase 2.1.b" en el combo de Cross-validation.
7. **H7:** Umbral de matriz de clasificación en 0.5 por defecto + warning amber si recall=0.

### 0.2 Lo que 3.10.b SÍ entrega (Backend + Frontend)
1. **Cortes Candidatos (Panel Inferior):** Un panel inferior que muestra los top-N cortes alternativos evaluados por el motor (con WOE, IV, Odds).
   - *Requisito:* Modificar `TreeNode` y `TreeBuilder` para almacenar y exponer el historial de splits candidatos, no solo el ganador.

### 0.3 Lo que NO entrega
- Cambios en la lógica analítica ni en los motores (excepto la recolección de candidatos en 3.10.b).
- Renumeración de las fases 4 a 7 del roadmap.

## §1. Decisiones de Diseño (UI)

### 1.1 Arquitectura de la Toolbar (3.10.a)
- Usar `QToolBar` con `QAction` (iconos + texto).
- Las acciones ya existen en los menús; la toolbar las reutiliza o crea accesos directos visuales.

### 1.2 Nodos Enriquecidos (3.10.a)
- `NodeItem` pasará de un simple texto a un layout tipo widget (o se dibujará con `QPainter`).
- **Cabecera:** Fondo de color. El color de fondo de la cabecera de un nodo interno será el `ACCENT`; para hojas será dinámico: rojo (PD > umbral_alto), naranja (medio), verde (bajo).
- **Cuerpo:** Tabla compacta: `Clase | n | %`.
- **Footer:** Gini, KS, P-val.

### 1.3 Panel de Propiedades Derecho (3.10.a)
- Sustituye el `hudBody` actual por un `QScrollArea` con `QGroupBox` colapsables.
- Secciones: Dataset, Nodo Seleccionado (con barra de progreso roja/verde), Regla de Partición, Acciones.

### 1.4 Tema Oscuro (H8) (3.10.a)
- Actualizar `theme.py`:
  - `BG` = `#1E1E1E` (fondo profundo)
  - `SURFACE` = `#252526` (paneles)
  - `SURFACE_ELEVATED` = `#333333` (nodos/tarjetas)
- Actualizar `styles.qss` para usar el nuevo token.

### 1.5 H3, H5, H7 (3.10.a)
- (H3) Iconos unicode en `wizard.py`.
- (H5) Tooltip explicativo.
- (H7) Lógica de warning en `reports_panel.py`.
