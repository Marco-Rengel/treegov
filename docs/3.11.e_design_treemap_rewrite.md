# Fase 3.11.e — Diseño: Rediseño del Tree Map desde Cero (Clean Room)

**Estado:** ✅ Implementado (31/10/2026). Supersede §D2 de
`docs/3.11.b_design_treemap_dataviewer.md` y el §18.11 de
`docs/design_decisions.md` en lo relativo al port del prototipo.

## §0. Motivo

El widget `frontend_v3/tree_map.py` previo contenía un port del prototipo
Antigravity (constantes, algoritmo y colores hex idénticos), lo que
violaba `design_decisions.md` §0.5 y `.treegovrules` §Prohibitions. Se
reescribe íntegramente desde cero sin reutilizar nada del prototipo.

## §1. Lecciones de las iteraciones #4-#8

1. Texto escalado con la escena -> ilegible a fitInView bajo.
2. Navegación por coordenadas -> frágil ante divergencias de layout.
3. Compresión por fitInView -> destruye legibilidad.
4. Acoplamiento estético con el canvas -> problemas heredados.
5. Acoplamiento con el prototipo -> rompe Clean Room.

## §2. Decisiones de arquitectura

| ID | Decisión | Cita |
|---|---|---|
| D1 | Layout tidy tree ordenado arriba-abajo, constantes propias (48x30, gaps 16/36). | Reingold & Tilford (1981), IEEE TSE 7(2), 223-228. |
| D2 | Líneas ortogonales de 3 tramos (baja, horizontal, entra). | Battista, Eades, Tamassia & Tollis (1998), Graph Drawing, cap. 4. |
| D3 | Colores desde PALETTES del Design System. | 3.11_gui_design_system.md §2.1. |
| D4 | ID con ItemIgnoresTransformations, 8 pt. | Qt 6 docs, QGraphicsItem::ItemIgnoresTransformations. |
| D5 | fitInView con MIN_SCALE=0.02 + scrollbars si el fit real es menor. | Lección #3. |
| D6 | Clic emite node_id (no coordenadas). | Lección #2. |
| D7 | Empty state sin branding. | Coherencia con DataViewer. |

## §3. Invariantes

- Cero código del prototipo.
- Cero lógica analítica en el frontend (sala limpia).
- Determinismo de layout.
- Interfaz pública estable (set_model, set_selected_node, set_theme,
  node_clicked).
