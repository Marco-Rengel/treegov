# Fase 3.11.d — Diseño: Menú Contextual e Interactividad

## 1. Contexto y Alcance

La Fase 3.11.d cierra la Fase 3.11 añadiendo el menú contextual sobre los nodos del árbol y el Manual Override Log. Con esta fase, el analista podrá crecer, podar y modificar splits manualmente desde la interfaz gráfica, interactuando directamente con los nodos renderizados.

El comportamiento depende del modo de operación:

- **Modo RESEARCH:** la intervención manual es libre; las acciones se aplican directamente sin fricción adicional.
- **Modo BANKING:** la intervención manual requiere auditoría estricta: cada acción pedirá confirmación explícita y quedará registrada en el Manual Override Log. Además, la intervención alterará el fingerprint del modelo, marcándolo como intervenido manualmente.

## 2. Menú Contextual del Nodo (Frontend)

- El menú se activa con clic derecho sobre un `NodeItem` en `tree_view.py`.
- Opciones del menú:
  - **Grow Tree** — crece el árbol desde la hoja seleccionada.
  - **Prune Branch** — poda la rama que cuelga del nodo seleccionado.
  - **Select Predictor** — permite elegir manualmente la variable predictora del split.
  - **Define Split** — permite definir manualmente el punto de corte del split.
- Reglas de habilitación:
  - El menú contextual completo se deshabilitará si el árbol no está en estado TRAINED.
  - Para las acciones Grow Tree, Define Split y Select Predictor, la opción correspondiente se deshabilitará si el nodo no es una hoja.
- El menú emitirá señales Qt específicas (una por acción, con el `node_id` como argumento) que `MainWindow` capturará y traducirá en llamadas al backend.

## 3. Interactividad Backend (Zonas Grises Resueltas)

Para evitar romper la inmutabilidad del modelo y el orden BFS, se define la siguiente estrategia:

- **Aislamiento de datos:** dado un `node_id`, `Session` debe recuperar las filas del nodo original. Usará `validation.predict_leaf_assignment` sobre el dataset original para filtrar los índices correspondientes al nodo.
- **Nuevo método en Session:** `intervene_node(node_id, action, payload)`. Es el punto de entrada único del backend para toda intervención manual.
- **Grow Tree / Prune Branch:** reutilizarán la lógica existente. Grow evaluará el mejor split con el motor actual sobre el subconjunto de datos del nodo. Prune Branch no usará el `Pruner` global. Eliminará directamente los descendientes del nodo seleccionado, lo convertirá en hoja, y aplicará el mismo re-indexado BFS que usa la poda.
- **Define Split / Select Predictor:** forzarán un `SplitConfig` específico sobre el subconjunto de datos del nodo y calcularán los nodos hijos usando las fórmulas de Jeffreys de `TreeBuilder`. El backend debe validar que el `SplitConfig` forzado es válido (que genera al menos dos ramas con >= min_child_size filas cada una). Si el split forzado deja alguna rama vacía o con menos filas del mínimo, el backend lanzará `ValueError` y la UI mostrará un mensaje de error. El estado del modelo no se alterará.
- **Reconstrucción del Árbol:** dado que `TreeModel` es frozen, se creará un nuevo `TreeModel`. Se reemplazará el nodo hoja por el nuevo subárbol y se hará un re-indexado BFS completo (similar a `pruning.py::_rebuild`) para mantener la invariante `node_id == index`.
- **Fingerprint:** el nuevo `TreeModel` heredará el fingerprint del original pero se le añadirá un sufijo de intervención manual (ej. `-i1`, `-i2`, incremental por sesión) y se guardará el registro en el Manual Override Log.

## 4. Manual Override Log (Gobernanza)

- Toda acción manual se registrará en `SessionState.manual_overrides` como una tupla de diccionarios con los campos: `(timestamp, node_id, action, params, fingerprint_before, fingerprint_after)`.
- El botón "Ver Auditoría" en el HUD derecho abrirá un diálogo mostrando este log.
- En modo BANKING: `MainWindow` pedirá confirmación explícita (QMessageBox) antes de llamar a `intervene_node`.
- En modo RESEARCH: la acción se aplicará directamente, sin diálogo de confirmación (pero igualmente quedará registrada en el log).

## 5. Sub-fases

- **3.11.d.1**: Backend interactivo (`Session.intervene_node`, re-indexado BFS, `manual_overrides` en `SessionState`, tests).
- **3.11.d.2**: Frontend (Menú contextual en `tree_view.py`, señales y confirmación en `main_window.py`).
- **3.11.d.3**: Diálogo del Manual Override Log y botón "Ver Auditoría" en el HUD.

## 6. Invariantes

- Sala limpia: el backend no importa Qt/PySide6; el frontend no contiene lógica analítica.
- El `TreeModel` original no se muta: toda intervención crea un `TreeModel` nuevo.
- La paridad K=2 para modelos entrenados normalmente no se ve afectada: la intervención manual es una acción posterior al entrenamiento.
- El re-indexado BFS asegura que no haya nodos huérfanos y que se mantenga la invariante `node_id == index`.
