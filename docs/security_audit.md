# TreeGov — Security and Privacy Audit (Phase 3.7.a)

**Purpose.** This document fulfills the requirements of Phase 3.7.a of the roadmap: a dedicated security and privacy audit of TreeGov before the v1.0.0 stable release. It defines the threat model, the data retention policy for logs, and the GUI warnings implemented to prevent accidental data leakage.

**Audience.** MRM auditors, security reviewers, and the project author.

## §0. Scope

TreeGov is a desktop application. It has no server, no remote authentication, no database, and no internet connection at runtime. The analyst loads a CSV, trains a model locally, and exports reports. 

This document covers the risks associated with **local data leakage** via the artefacts TreeGov generates. The sensitive output channels are:

- DEBUG logs (`logs/`) and exported HTML reports (original scope, Phase 3.7.a).
- **Production exports**: the SQL, Python and Markdown artefacts generated by the Phase 4.0 exporters, which embed the split rules, the training-time imputation values and the model fingerprint.
- **Batch Scoring CSVs** (Phase 6.0): the scored output file carries per-row leaf assignment, PD vector and rule path for the whole scored portfolio.
- **Clipboard copies**: the Ctrl+C → TSV copy of any data table (`ReportsPanel`, gains table, classification matrix), which leaves the process and lands in the OS clipboard, outside TreeGov's control.

## §1. Threat Model

### 1.1 Assets
- **The Dataset**: The CSV loaded by the analyst. Can contain sensitive PII or confidential financial data.
- **The Model**: The trained tree, including split rules, segment counts, and PD values.
- **The Artefacts**: The DEBUG logs (written to `logs/`), the exported
  HTML reports, the SQL/Python/Markdown files produced by the Phase 4.0
  exporters, the Batch Scoring CSVs written by `score_batch` (Phase 6.0)
  and any clipboard payload created with Ctrl+C → TSV on a data table.

### 1.2 Threat Vectors
- **Accidental Sharing of Logs**: A developer or analyst shares a `treegov_*.log` file for debugging, unaware that it contains real column names, file paths, and per-node PDs.
- **Accidental Sharing of Reports**: An analyst emails an HTML report to a colleague. The report contains the full gains table, classification matrix, and segment PDs.
- **Unintended GUI Exposure**: A screenshot of the TreeGov interface (e.g., the Tree Viewer or Reports panel) shared publicly reveals the structure of a proprietary model.

### 1.3 Mitigations
- **Log Retention Policy**: Explicit documentation that logs are ephemeral and should be cleaned.
- **GUI Warnings**: An explicit modal warning upon loading a dataset, reminding the analyst that the data and logs are confidential.
- **Documentation**: This document, serving as a reference for the institution's internal policies.

## §2. Log Retention and Cleanup

The `backend_v3.log_config` module writes to `logs/treegov.log` with `DEBUG` level. When training on real data, this log records:
- Column names from the CSV.
- PD per node and leaf distributions.
- File paths.
- Model fingerprints.

**Policy:** TreeGov does not auto-delete logs. The logs are owned by the analyst and subject to their institution's data retention policy. The analyst is responsible for deleting the `logs/` directory when the analysis is complete, or when moving the dataset off the machine.

## §3. HTML Reports

The `ReportsPanel` exports a self-contained HTML file. This file contains the gains table, classification matrix, and summary metrics. 

**Policy:** An exported HTML report is as sensitive as the dataset itself. It must be stored and transmitted according to the institution's data classification rules. TreeGov cannot enforce this once the file is saved to disk; it is the analyst's responsibility.

## §4. GUI Warnings

To mitigate the risk of accidental leakage, TreeGov implements a mandatory, non-blocking warning upon the first dataset load in a session. The warning reminds the analyst that:
- The dataset and generated logs are confidential.
- The logs must be cleaned up.
- The GUI does not encrypt files on disk.

This warning is shown once per session to avoid friction, but its presence is recorded in the log. 

### §5. Auditoría de seguridad de la Capa MCP (Fase 5.0)

**Riesgos aceptados:**
- **Acceso a rutas locales:** `load_dataset` y `load_oot` permiten
  rutas absolutas. El servidor MCP corre bajo el usuario del SO y
  tiene los mismos permisos de lectura que la GUI. Se documenta como
  responsabilidad del analista.
- **Transporte:** Solo stdio local (D5). Sin puertos abiertos ni
  telemetría. El protocolo MCP no persiste datos fuera del proceso.

**Mitigaciones implementadas:**
- Invariante I-7: el servidor no escribe en disco excepto los logs
  locales vía `log_config`.
- D11: sin herramientas de exploración de directorios (browsing/glob).

## §6. Auditoría de la Fase 6 (Batch Scoring y MCP)

**Excepción acotada a I-7.** La tool `score_batch` permite escritura en disco
mediante el `output_path` explícito y obligatorio. Esta escritura es una
excepción limitada a la restricción general de la Fase 5, que solo permitía los
logs locales: el servidor no habilita browsing, glob ni una capacidad genérica
de exportación. La operación permanece local sobre stdio, sin red ni telemetría.

**Mitigaciones implementadas.**
- El destino debe ser proporcionado por el llamador; no se deriva ni se explora
  ningún directorio.
- El scoring se ejecuta localmente y publica el CSV mediante un temporal en la
  carpeta de destino, evitando una salida final parcial si la operación falla.
- El retorno MCP contiene un resumen acotado, no el contenido completo del CSV.

**Política de overwrite.** La protección anti-overwrite está implementada:
`score_batch_to_csv` lanza `FileExistsError` antes de crear el archivo
temporal si `output_csv` ya existe (hotfix del 02/11/2026). El llamador debe
elegir una ruta nueva; no se sobrescribe ningún artefacto existente.

**Champion-Challenger.** `compare_champion_challenger` no escribe archivos: solo
lee el CSV de evaluación indicado y devuelve el DTO de comparación en memoria.
No publica modelos, predicciones ni artefactos adicionales en disco.
