# TreeGov — Phase 3.7 design: Pre-release fixes
*(Documento creado en retrospectiva el 21/10/2026 para cumplir con el Playbook)*

**Propósito.** Definir las correcciones aplicadas antes del primer Release Candidate (v1.0.0rc1).

## Contexto
Tras la sesión de visualización de la GUI (13/10/2026), se identificaron hallazgos UX (H1, H2) y un bug numérico de límites (PD floor en K=2). Además, el KS por pares en multiclase era asimétrico.

## Decisiones y Sub-fases
- **3.7.a (Seguridad):** Añadir aviso modal en la GUI sobre logs y datos sensibles (`docs/security_audit.md`).
- **3.7.b (Simetrización KS):** Promediar el KS directo e inverso en multiclase para alinearlo con el AUC de Hand & Till.
- **3.7.c (min_child_weight):** Exponer este parámetro (creado en 3.2) en la firma pública de `Session.train` y en el wizard.
- **3.7.d (Tests UCI):** Ampliar los tests de integración para incluir CHAID y QUEST además de C&RT.
- **3.7.e (Fixes UI y PD Floor):** 
  - **H1:** Hacer visibles los radio buttons del wizard (QSS).
  - **H2:** Forzar la selección explícita del target (placeholder) en lugar de elegir la primera columna.
  - **PD Floor K=2:** Cambiar el "soft floor" por un "hard floor" estricto para cumplir con BCBS CRE 32.4.
